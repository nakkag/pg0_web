What the API offers

PG0 (Web) provides an HTTP API for AI agents. Through it an agent can:

Write and verify

Write PG0 / PG0.5 programs, check the syntax and run them to confirm the behaviour.

Save

Save programs online and get a URL that opens them in this editor. Revisions are kept.

Test games too

Games that use the screen library can be exercised with timed key and touch input.

The detailed specification the agent itself reads (API usage, language, libraries) is at the URLs below. Tell the agent to read the manual first.

Agent manual
https://pg0.jp/api/agent/v1/manual?lang=en (English) / https://pg0.jp/api/agent/v1/manual?lang=ja (Japanese)
Machine-readable definitions
https://pg0.jp/api/agent/v1/openapi.json (OpenAPI) / https://pg0.jp/api/agent/v1/libraries (function list) / https://pg0.jp/api/agent/v1 (index and limits)
Entry point for agents
https://pg0.jp/llms.txt

What you need

  • An AI agent that can access the web (send HTTP requests). For example Claude Code, a chat AI with web access or code execution, or an agent you built yourself.
  • No API key. Anyone can use the API.
  • A password for saving. It is needed later for updates and deletion. Let the agent choose one or give it in your instructions.

Basic workflow

  1. The agent reads the manual (URL above) to learn the language and the libraries
  2. It writes the program and checks the syntax with /check (typical mistakes come back as warnings)
  3. It runs the program with /run and inspects output, return value and variables
  4. Steps 2 and 3 are repeated until the program behaves as expected
  5. It saves the program online with /scripts (name, author, password, memo)
  6. You open the URL the agent reports and run the program in the editor
  7. When you ask for changes, the agent updates the same script and writes what changed into the memo (revision history)

Saved programs can also be found with "Open online" in the editor, searching by name or author.

Example instructions

Telling the agent to read the manual URL first is the most reliable start. Copy and adapt these examples.

An ordinary program

Create a program in PG0.5. First read https://pg0.jp/api/agent/v1/manual?lang=en to learn the
language and the API, verify the program with /check and /run, then save it online with /scripts.
Task: print the prime numbers from 1 to 100.
Save it as "Prime numbers", author "(your name)", password "(any string)", public.
Finally tell me the URL that opens it in the editor.

A game

Using the screen library of PG0.5 (lib/screen.pg0), create a touch-controlled breakout game.
Read https://pg0.jp/api/agent/v1/manual?lang=en and verify the game logic with headless runs.
Since it is a screen program, save it with execution speed "No wait" (speed: 0) and give me the
URL that opens and runs it immediately (run_url).

Modifying a saved program

Give the agent the cid (script id) and the password. The cid is the string after ?cid= in the URL.

Fetch the script with cid xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx and change it so that the ball gets
10% faster on every stage. The password is "(the string used when saving)".
When you update it, describe the change in the memo.

PG0 mode for learning

You can also ask for the smaller PG0 mode (integers only, no functions).

In PG0 mode (integers only, no functions), write a program that builds the multiplication table using
only while loops. Leave the result in variables and verify it with the "variables" field of /run.

Rules for saving online

  • Names must be unique among public scripts; saving fails if the name exists (private scripts may repeat names).
  • The password is needed for updates and deletion. It works exactly like a password entered in the editor, so a person can update an agent's script in the editor and vice versa. It is compared case-insensitively with surrounding spaces removed.
  • The memo is kept per version and shown in the editor's "Revision history". Tell the agent to describe the program on creation and the change on every update.
  • Public scripts are visible to everyone. Do not put personal information in them.
Two URLs from the agenturl opens the script in the editor; run_url opens it and runs it immediately, which is convenient for handing a game to someone.
About passwordsThis is not strong protection. Do not rely on it for anything valuable.

Screen (game) programs

  • Programs that use the screen library (lib/screen.pg0) run through the API without a screen (headless). Drawing calls are recorded, and key or touch input can be given with timestamps to verify the game logic.
  • Appearance (layout, colors) cannot be checked through the API; open the program in the editor for that.
  • Have the agent save such programs with execution speed "No wait" (speed: 0). Other speeds pause after every statement and make screen programs extremely slow.
  • Because of browser restrictions, sound may not play before the first tap or key press.

API overview

Everything lives under https://pg0.jp/api/agent/v1 with JSON requests and responses. Details are in the agent manual.

MethodPathPurpose
GET/manual?lang=en|jaManual (Markdown)
GET/openapi.jsonOpenAPI description
GET/librariesFunction list
POST/checkSyntax check (with warnings)
POST/runRun (returns output, result, variables, screen recording)
GET/scriptsList / search saved scripts
POST/scriptsSave a new script
GET/scripts/{cid}Get a script including its code
PUT/scripts/{cid}Update (password required)
DELETE/scripts/{cid}Delete (password required)
POST/scripts/{cid}/runRun a saved script
GET/scripts/{cid}/historyRevision history

Quick test with curl

curl -H "Content-Type: application/json" \
     -d '{"code":"#import(\"lib/io.pg0\")\nfor (i = 1; i <= 3; i++) { println(i * i) }"}' \
     https://pg0.jp/api/agent/v1/run

{"status":"ok","output":"1\n4\n9\n", ...}

Limits

  • One run is limited to 5 seconds by default (30 seconds at most); the number of executed statements and the memory are capped too. Split long work, or for games use the frame limit (max_frames).
  • The number of concurrent runs is limited; beyond it the API asks to retry after a short wait (429).
  • The actual values are listed under limits at https://pg0.jp/api/agent/v1.
  • Only lib/math.pg0, lib/string.pg0, lib/io.pg0 and lib/screen.pg0 can be imported with #import; URLs and other files cannot.

Troubleshooting

SymptomWhat to do
Saving reports a name conflict (409)Use another name or save as private (private: 1).
Updating or deleting reports a wrong password (401)Give the agent the password used when saving.
A run ends with status: "timeout"Endless loop or too much work; for screen programs have the agent set max_frames.
"Read error in script or library"An unsupported #import is used.
The agent misunderstands the language (braces after if, block-local variables, string operators, ...)Tell it to read the "Pitfalls checklist" in the manual.
